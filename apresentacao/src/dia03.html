Fluxograma: o algoritmo desenhado

  • Terminal (oval): início e fim.
  • Processo (retângulo): uma ação ou um cálculo.
  • Entrada/saída (paralelogramo): ler um botão, um sensor, o serial; mostrar uma mensagem.
  • Decisão (losango): uma pergunta com resposta sim ou não. Vira um if.
  • Setas: mostram a ordem. Uma seta que volta para cima é uma repetição.

Toda prática desta UC começa pelo fluxograma: se o desenho está certo, o código sai quase sozinho.

Estruturas de decisão: if, else if, else

  • if (condição) { … } executa o bloco só se a condição for verdadeira.
  • else é o caminho do “não”.
  • else if encadeia várias faixas: a primeira verdadeira vence, as outras são ignoradas.
  • A condição usa as expressões relacionais e lógicas do dia 2.

Decisão por casos: switch

  • Compara uma variável com vários valores fixos (números ou caracteres).
  • Cada case termina com break; sem ele, a execução “cai” no caso seguinte.
  • default trata qualquer valor não previsto.
  • Ideal para menus e comandos recebidos pelo serial e para máquinas de estado.

Estruturas de repetição: for, while, do…while

for

Quando se sabe quantas vezes repetir.

for (int i = 0; i < 5; i++)
início · condição · passo

while

Repete enquanto a condição for verdadeira. Testa antes: pode não executar nenhuma vez.

do … while

Executa e depois testa: roda pelo menos uma vez.

O próprio loop() já é uma repetição infinita. Um while ou delay longo bloqueia o programa: nada mais é lido enquanto ele roda.

Entrada digital: botões e resistor de pull-up

  • digitalRead(pino) devolve HIGH (≈ 5 V) ou LOW (≈ 0 V).
  • Pino sem nada ligado fica flutuando e lê valores aleatórios.
  • pinMode(pino, INPUT_PULLUP) liga um resistor interno ao 5 V: o botão vai do pino ao GND, sem resistor externo.
  • Com pull-up a lógica é invertida: apertado = LOW.
bool apertado = digitalRead(2) == LOW;

Detectar o toque, não o botão apertado

O loop() roda milhares de vezes por segundo. Se o código só pergunta “está apertado?”, um toque vira centenas de comandos.

  • Borda de descida: agora está apertado e antes não estava.
  • Guarde o estado anterior numa variável e compare.
  • Bounce: o contato mecânico trepida por alguns milissegundos. Um delay(30) após a borda resolve nos botões comuns.

Entrada de dados pelo monitor serial

ComandoO que faz
Serial.available()Quantos bytes chegaram e ainda não foram lidos (0 = nada novo).
Serial.read()Lê um caractere (char) e o retira da fila.
Serial.parseInt()Lê os dígitos e devolve um número inteiro. parseFloat() devolve float.
Serial.readStringUntil('\n')Lê um texto até o Enter.

Sempre pergunte antes

if (Serial.available() > 0): só lê se chegou algo. Assim o loop continua livre.

Fim de linha

O monitor envia um Enter ('\n') após o texto. Ignore esse caractere no switch ou esvazie a fila depois de ler.
